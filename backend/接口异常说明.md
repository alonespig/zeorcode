# ZOJ 接口异常说明

本文档记录 ZOJ 后端当前统一响应格式、业务错误码，以及相关接口可能返回的异常。内容以当前代码实现为准，最后核对日期为 2026-08-23。

## 1. 响应约定

除文件下载和 SSE 长连接外，接口使用统一 JSON 响应。

成功示例：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

失败示例：

```json
{
  "code": 40010,
  "msg": "尚未报名该比赛"
}
```

当前服务的普通 JSON 接口在业务失败时仍返回 HTTP 200，前端必须判断响应体中的 `code`，不能只判断 HTTP 状态码。

- `code = 200`：业务成功。
- `code != 200`：业务失败，按 `code` 处理，`msg` 用于向用户展示。
- 同一错误码的 `msg` 可能根据场景细化，前端业务分支应依赖 `code`，不要依赖完整文案。
- 底层数据库、Redis、文件路径和第三方错误仅保留在服务端错误链中，不通过标准 JSON 响应返回。

## 2. 通用错误

以下错误可能出现在多个接口中。

| 业务码 | 默认提示 | 触发条件 | 前端建议 |
| --- | --- | --- | --- |
| `10001` | 参数错误 | JSON、查询参数或路径参数格式不正确，或者必填字段缺失 | 保留页面并标记错误字段 |
| `10002` | 请求格式错误 | 请求不符合业务要求 | 展示 `msg` |
| `10003` | 请求过于频繁 | 命中登录、验证码或提交限流 | 禁用按钮并延迟重试 |
| `20001` | 未登录 | 受保护接口没有登录凭证 | 跳转登录或打开登录框 |
| `20002` | 登录已过期 | Token 过期或服务端会话已失效 | 清理本地登录态后重新登录 |
| `20003` | 登录凭证无效 | Token 无法解析或签名无效 | 清理本地登录态后重新登录 |
| `60002` | 需要管理员权限 | 普通用户访问管理员接口 | 返回上一页或显示无权限页 |
| `90000` | 未知错误 | 返回了未纳入统一错误体系的异常 | 展示统一失败提示并记录请求信息 |
| `90001` | 服务器内部错误 | 文件处理、消息派发、加密或其他内部操作失败 | 展示“服务暂时不可用”，不要展示内部细节 |
| `90002` | 数据库错误 | 数据库查询、事务或写入失败 | 展示统一失败提示，避免自动重复写请求 |
| `90003` | Redis 错误 | 缓存、会话、验证码或限流存储异常 | 提示稍后重试 |
| `90004` | 文件上传失败 | 测试数据文件保存失败 | 保留用户选择的文件并允许重新上传 |

## 3. 比赛接口

### 3.1 报名比赛

`POST /api/contest/join`

请求示例：

```json
{
  "id": 12,
  "inviteCode": "ZOJ"
}
```

| 业务码 | 提示 | 触发条件 |
| --- | --- | --- |
| `10001` | 参数错误 | `id` 未传或请求体格式错误 |
| `20001` / `20002` / `20003` | 登录相关错误 | 未登录、登录过期或 Token 非法 |
| `40003` | 比赛不存在 | 比赛 ID 不存在 |
| `40007` | 比赛已结束 | 当前时间已到达或超过比赛结束时间 |
| `40008` | 已报名该比赛 | 用户重复报名，包括并发重复请求 |
| `40009` | 邀请码错误 | 私有比赛的邀请码为空或不匹配 |
| `90002` | 数据库错误 | 查询比赛、查询报名状态或写入报名记录失败 |

比赛进行中仍允许报名；比赛结束后禁止报名。

### 3.2 获取比赛题目列表

`GET /api/contest/:id/problem`

| 业务码 | 提示 | 触发条件 |
| --- | --- | --- |

| `40003` | 比赛不存在 | 比赛 ID 不存在 |
| `40004` | 比赛未开始 | 普通用户在开赛前访问 |
| `40010` | 尚未报名该比赛 | 普通用户未报名该比赛 |
| `90002` | 数据库错误 | 读取比赛题目、提交状态或统计失败 |

管理员不受开赛时间和报名状态限制，可以提前查看。

### 3.3 获取比赛题目详情

| `40004` | 比赛未开始 | 普通用户在开赛前访问 |

### 3.5 提交比赛题目

`POST /api/contest/submit`

请求示例：

```json
{
  "contestId": 12,
  "label": "A",
  "code": "int main() { return 0; }",
  "language": 1
}
```

`language` 当前仅支持：`1 = C++`、`2 = Java`、`3 = Python`。

| 业务码 | 提示 | 触发条件 |
| --- | --- | --- |
| `10001` | 参数错误 | 请求体格式错误或必填字段缺失 |
| `10003` | 提交过于频繁，请稍后再试 | 同一用户短时间重复提交 |
| `20001` / `20002` / `20003` | 登录相关错误 | 登录状态不可用 |
| `40003` | 比赛不存在 | 比赛 ID 不存在 |
| `40004` | 比赛未开始 | 当前时间早于开始时间 |
| `40005` | 题目暂无测试数据，暂时无法提交 | 本地题没有完整、有效的测试数据 |
| `40007` | 比赛已结束 | 当前时间已到达或超过结束时间 |
| `40010` | 尚未报名该比赛 | 用户未报名比赛 |
| `40011` | 比赛题目不存在 | `label` 不属于该比赛 |
| `50006` | 不支持的编程语言 | `language` 不是 `1`、`2`、`3` |
| `90001` | 提交入队失败 | 提交已写入数据库，但即时派发判题失败 |
| `90002` | 数据库错误 | 创建提交或读取比赛题目失败 |
| `90003` | Redis 错误 | 提交限流存储不可用 |

遇到“提交入队失败”时，前端不要自动重复提交源码。后端已经保存 Submission 和 Outbox，会由派发任务继续重试；前端可以跳转提交详情或提示用户稍后刷新。

### 3.6 获取比赛提交列表

`GET /api/contest/:id/submission`

- 普通用户只返回自己的提交，传入的用户、题目和结果筛选会被忽略。
- 管理员可以查看全场提交并使用筛选条件。
- 返回项不包含源码。

可能返回 `10001`、登录相关错误、`40003` 和 `90002`。

### 3.7 比赛时间兼容规则

- `Duration` 单位固定为分钟。
- 比赛状态优先使用 `EndTime`。
- 旧数据没有 `EndTime` 时，结束时间按 `StartTime + Duration * time.Minute` 计算。
- 当前时间等于结束时间时，比赛视为已结束，不能继续报名或提交。

`POST /api/submission`

请求字段与比赛提交类似，但题目使用对外题号：

```json
{
  "problemID": "P1000",
  "code": "print(1)",
  "language": 3
}
```

| 业务码 | 提示 | 触发条件 |
| --- | --- | --- |
| `10001` | 参数错误 | 请求体格式错误或必填字段缺失 |
| `10003` | 提交过于频繁，请稍后再试 | 同一用户短时间重复提交 |
| `20001` / `20002` / `20003` | 登录相关错误 | 登录状态不可用 |
| `40001` | 题目不存在 | 题号不存在；普通用户提交隐藏题时也返回此错误 |
| `40005` | 题目暂无测试数据，暂时无法提交 | 本地题测试数据不完整 |
| `50006` | 不支持的编程语言 | `language` 不是 `1`、`2`、`3` |
| `90001` | 提交入队失败 | 提交已持久化，但即时入队失败 |
| `90002` | 数据库错误 | 创建提交失败 |
| `90003` | Redis 错误 | 提交限流存储不可用 |

### 5.2 获取提交详情

`GET /api/submission/:id`

| 业务码 | 提示 | 触发条件 |
| --- | --- | --- |
| `10001` | 参数错误 | 提交 ID 格式错误 |
| `30001` | 用户不存在 | 提交关联的作者数据不存在 |
| `40001` | 题目不存在 | 关联题目不存在，或普通用户访问隐藏题提交 |
| `50005` | 提交记录不存在 | 提交 ID 不存在 |
| `90002` | 数据库错误 | 查询提交、测试点结果、题目或作者失败 |

源码可见性规则：

- 提交者本人可以看到 `data.submission.code`。
- 管理员可以看到任意提交的源码。
- 其他用户和匿名用户收到的 `data.submission.code` 固定为空字符串。
- 当前实现不只限制比赛进行中；非本人、非管理员在比赛结束后同样看不到源码。

### 5.3 判题实时事件

`GET /api/submission/:id/stream`

该接口是 SSE 长连接，不使用统一 JSON 错误响应。事件类型包括 `judging` 和 `done`。

事件中的 `submission` 只包含以下状态字段，不包含 `code`：

```json
{
  "submission": {
    "id": 123,
    "language": "c++",
    "status": 1,
    "time": 12,
    "memory": 1024,
    "createdAt": "2026-08-23 10:00:00"
  },
  "caseResults": []
}
```

路径参数非法或连接中断时，连接可能直接关闭，前端应监听 `EventSource.onerror`，不要等待标准业务错误体。

- `POST /api/admin/contest/:id/problem/:pid/rejudge`

| --- | --- | --- |

| `60002` | 需要管理员权限 | 非管理员调用 |

| `90002` | 数据库错误 | 查询或重置提交失败 |

## 6. 用户管理接口

以下接口仅管理员可用，路径中的 `:id` 均为对外用户号，不是内部主键。

### 6.1 封禁与解封用户

`PUT /api/admin/users/:id/status`

请求示例：

```json
{
  "status": 1
}
```

`status` 只接受 `0`（正常）和 `1`（封禁）。封禁会同时撤销该用户的会话，现有 Token 在下一次请求即失效，相当于立即踢下线；解封不影响会话。

管理员不能被封禁，需要先把其角色改为普通用户（见 6.2）再封禁。

| 业务码 | 提示 | 触发条件 |
| --- | --- | --- |
| `10001` | 非法用户号 / 参数错误 | 路径参数不是整数，或 `status` 不在 `0`、`1` 之内 |
| `30001` | 用户不存在 | 对外用户号查不到对应用户 |
| `60002` | 需要管理员权限 | 非管理员调用 |
| `60003` | 不能封禁管理员 | 目标用户当前是管理员 |
| `90002` | 数据库错误 | 写入用户状态失败 |

### 6.2 修改用户角色

`PUT /api/admin/users/:id/role`

请求示例：

```json
{
  "role": 1
}
```

`role` 只接受 `0`（普通用户）和 `1`（管理员）。管理员之间是平级的，可以互相升级或降级。

该接口会撤销目标用户的会话，被修改者需要重新登录，新角色才会生效。这是必需的：管理员权限中间件只校验 Token 中签发时写入的角色声明、不回查数据库，如果不撤销会话，被降级者在 Token 过期前仍然可以访问管理员接口。

若目标用户当前角色与请求一致，接口按成功返回，但不会写库，也不会撤销其会话。

| 业务码 | 提示 | 触发条件 |
| --- | --- | --- |
| `10001` | 非法用户号 / 非法角色 | 路径参数不是整数，或 `role` 不在 `0`、`1` 之内 |
| `30001` | 用户不存在 | 对外用户号查不到对应用户 |
| `60002` | 需要管理员权限 | 非管理员调用 |
| `60003` | 不能修改自己的角色 | 目标用户就是当前登录的管理员本人 |
| `90002` | 数据库错误 | 写入用户角色失败 |

验证码校验成功后会立即删除，同一个验证码不能重复使用。

## 8. 讨论、帖子和评论接口

### 8.1 帖子不存在

以下接口在帖子 ID 不存在时返回 `70001`：

- `GET /api/posts/:id`
- `GET /api/posts/:id/comments`
- `PUT /api/posts/:id`
- `DELETE /api/posts/:id`
- `POST /api/posts/:id/like`
- `POST /api/posts/:id/comments`
- `PUT /api/admin/posts/:id/review`

未通过审核的帖子被非作者、非管理员访问时，同样返回 `70001`，避免泄露帖子是否存在。

### 8.2 评论不存在

以下情况返回 `70002`：

- 点赞的评论不存在：`POST /api/comments/:cid/like`。
- 删除的评论不存在：`DELETE /api/comments/:cid`。
- 创建回复时 `parentID` 不存在。
- `parentID` 对应的评论不属于当前帖子。

### 8.3 其他讨论区异常

| 业务码 | 提示 | 触发条件 |
| --- | --- | --- |
| `10001` | 参数错误 | 分类、标题、内容、审核状态或路径 ID 不合法 |
| `40001` | 题目不存在 | 题解或求助关联的对外题号不存在 |
| `60003` | 非本人操作 | 非作者、非管理员编辑或删除帖子、评论 |
| `70001` | 文章不存在 | 帖子不存在或当前用户不可见 |
| `70002` | 评论不存在 | 评论不存在或不属于目标帖子 |
| `90002` | 数据库错误 | 查询、创建、更新、点赞或删除失败 |

## 9. 远程 OJ 接口

### 9.1 拉取远程题目

`GET /api/remote/problem?oj=HDU&pid=1000`

该接口仅管理员可用。

| 业务码 | 提示 | 触发条件 |
| --- | --- | --- |
| `10001` | 缺少 oj 或 pid 参数 | 查询参数缺失 |
| `60002` | 需要管理员权限 | 非管理员调用 |
| `80001` | 不支持的远程 OJ | `oj` 没有对应实现 |
| `80002` | 远程题目暂时无法获取 | 远程站点不可用、题号不存在、页面解析失败或请求失败 |

`80002` 不向前端返回远程站点的原始响应或内部错误细节。

### 9.2 远程账号管理

- `GET /api/admin/remote-account`
- `POST /api/admin/remote-account`
- `PUT /api/admin/remote-account/:id`
- `DELETE /api/admin/remote-account/:id`

| 业务码 | 提示 | 触发条件 |
| --- | --- | --- |
| `10001` | 参数错误 / 非法 id | 请求字段或路径参数不合法 |
| `60002` | 需要管理员权限 | 非管理员调用 |
| `80003` | 远程账号不存在 | 更新或删除的账号 ID 不存在 |
| `90001` | 凭证加密失败 | 加密密码或 Cookie 失败 |
| `90002` | 数据库错误 | 账号查询、创建、更新或删除失败 |

账号列表只返回 `hasSecret`，不会返回明文或加密后的凭证。

## 10. 前端统一处理建议

建议在请求封装层集中处理以下错误：

| 错误范围 | 建议行为 |
| --- | --- |
| `20001`、`20002`、`20003` | 清理登录状态并引导重新登录 |
| `60002` | 显示无管理员权限页面 |
| `90000` 至 `90004` | 使用统一系统错误提示；可记录接口、业务码和请求追踪信息，但不要向用户展示内部堆栈 |

其余错误由业务页面处理，例如：

- `40004`：比赛页面显示倒计时，不请求题目详情。
- `40010`：提示先报名比赛。
- `40005`：禁用提交按钮并提示暂无测试数据。
- `40007`：停止提交并刷新比赛状态。
- `40008`：报名按钮切换为“已报名”。
- `50005`、`70001`、`70002`、`80003`：展示资源不存在状态，而不是通用系统错误。
- `30006`：保留验证码输入框并允许重新输入。
- `30007`：清空验证码并引导重新发送。

对于提交、报名、创建、更新、删除等写接口，不建议因 `90001`、`90002`、网络超时而自动重试。客户端无法仅凭错误判断服务端是否已经完成写入，自动重试可能造成重复操作。
