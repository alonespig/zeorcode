## 2. 项目概况

- 项目名称已由 FastOJ 统一调整为 **ZOJ**。
- Go module 为 `zoj`。
- 技术栈：Go、Gin、GORM、MySQL、Redis 与消息队列。
- HTTP 服务和判题进程分别由 `cmd/http`、`cmd/judge` 启动。
- 当前工作区在导出时是干净的，没有未提交代码。
- `go.mod`、`go.sum` 已纳入版本控制。
- 本地运行配置、测试数据、上传文件和运行时目录属于本地状态，不应随意覆盖或提交。

## 3. 架构方向

- 采用模块化单体和垂直业务模块，不拆微服务，不一次性搬迁全部旧代码。
- 目标业务模块包括：`account`、`problem`、`submission`、`contest`、`discussion`、`notification`、`remoteoj`、`judging`。
- 新代码及被重构代码的依赖方向为：`transport -> application -> domain`。
- 数据库、缓存、消息队列和外部系统实现属于 adapter。
- `platform`/`infra` 与 `bootstrap` 不得反向依赖业务模块。
- 旧的全局 `handler/service/repository/model/dto` 是渐进迁移区；新增功能不要继续扩大横向分层。
- Handler 只负责协议解析、认证信息提取、输入输出映射和 HTTP 状态码。
- Application/Service 不新增对 Gin、GORM、Redis 或消息队列具体客户端的直接依赖。
- 接口由使用方定义，保持小而明确；依赖在 `bootstrap` 中显式装配。
- 不要为了少量复用创建大而全的 `common` 或 `utils` 包。

## 4. 已确认的业务约束

- `Contest.Duration` 单位为分钟，必须大于 0。
- 比赛状态优先使用 `EndTime`；兼容旧数据时按 `StartTime + Duration * time.Minute` 计算结束时间。
- Contest 主记录和题目关联的创建、更新必须位于同一数据库事务。
- 比赛进行期间，提交源码仅提交者本人和管理员可见。
- 实时判题 SSE 事件不得携带源码。
- 本地题目没有测试数据时不允许提交；题目详情会向前端提供测试数据是否存在的信息。
- 管理员可以预览题目测试数据内容，但预览和上传均有限制，不能无限制读取大文件。

### 5.2 Submission 可靠派发

相关提交：

- `d15cdf9`：重构提交派发并引入事务 Outbox。
- `bfeb2d8`：完善判题消息幂等与可靠确认。
- `eca18f5`：实现 Submission Outbox Relay。
- `20123bf`：修复 Outbox 状态查询的 MySQL 语法错误。

关键设计：

- Submission 与 Outbox 在同一数据库事务中创建。
- Relay 负责把 Outbox 可靠投递到判题队列。
- Worker 只在结果可靠落库后确认消息，并对重复或过期版本进行幂等处理。
- GORM 查询 `status IN ?` 不能传 `[]uint8`，否则会被 MySQL 驱动绑定成二进制参数并生成无效 SQL；当前已改为整数切片。
- Outbox 查询补充了 DryRun SQL 回归测试和可选的 MySQL 集成测试。

MySQL 集成测试优先读取：

```text
ZOJ_TEST_MYSQL_DSN
```

同时兼容旧环境变量 `FASTOJ_TEST_MYSQL_DSN`。

## 6. 当前暂停、尚未实现的方案

### Submission 对外雪花 ID

用户曾考虑让提交列表返回雪花 ID，同时保持前端字段名仍为 `id`，随后明确要求暂不修改。

当前状态：**仅讨论过方案，没有修改任何代码，也没有数据库迁移。**

如果以后恢复该需求，推荐采用：

- 数据库自增 `submissions.id` 继续作为内部主键和 Outbox、JudgeResult、消息队列的关联键。
- 新增唯一的 `submissions.public_id` 作为对外提交 ID。
- 创建响应、普通提交列表、比赛提交列表、详情路由、SSE 路由和单条重判入口统一使用 `public_id`。
- 前端 JSON 字段仍叫 `id`，接口形态不变。
- 旧数据迁移时可先把 `public_id` 回填为原内部 ID，以兼容历史链接。
- 不要截断标准雪花 ID。若希望更短，可设计时间戳、节点号和序列号组成的紧凑型雪花 ID，并确保数据库唯一索引兜底。
- 若仍以 JSON number 返回，应保证 ID 不超过 JavaScript 的安全整数上限；否则应改为字符串。
- 多实例部署必须为不同实例配置不同节点号，并处理时钟回拨。

## 7. 修改和提交约定

- 修改前阅读目标包、调用方和相关测试，不只根据文件名判断职责。
- 默认保持已有对外行为；改变行为时需要明确说明并补测试。
- 大范围移动前先补特征测试或最小安全网，并调查调用方、实现方和装配点。
- 结构调整和行为修改分开提交。
- 不编辑生成文件 `internal/bootstrap/wire_gen.go`；修改 `wire.go` 后运行：

```powershell
go run github.com/google/wire/cmd/wire
```

- 保留用户已有未提交改动，不使用 reset、restore 或覆盖方式清理无关变化。
- Commit 标题说明结果，正文使用中文说明原因、关键设计和验证结果。
- 不把无关格式化、运行文件或其他用户改动混入提交。

## 8. 验证清单

修改 Go 代码后至少执行：

```powershell
gofmt -w <修改过的 Go 文件>
go test <相关包>
go test ./...
git diff --check
git status --short
```

结构或依赖装配发生变化时补充：

```powershell
go build ./...
go vet ./...
```

涉及并发、Worker、SSE、Outbox 或消息确认时，根据风险补充：

```powershell
go test -race ./...
```

提交前需要核对实际暂存文件和暂存差异，确认没有包含 `ojdata`、`runtime`、`uploads` 或本地配置。
