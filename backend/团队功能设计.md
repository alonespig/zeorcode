## 1. 目标

给 ZOJ 加"团队"：老师/队长建团队，往里布置**作业**，成员在作业里刷题，按 **IOI 计分**出排行榜。
典型场景是校集训队和课程班级——现有的"比赛"太重（有赛制、rating、封榜），"题单"又太轻（没有时间窗、没有成绩统计）。

团队内含四块：**概览 / 作业 / 成员 / 文件**。

## 2. 已确认的产品决策

| # | 决策 | 说明 |
|---|---|---|
| 1 | 团队分**公开 / 非公开** | 非公开需邀请码才能加入 |
| 2 | 作业**不需要**邀请码 | 只要是团队成员就能做 |
| 3 | 作业有**开始时间 + 结束时间** | 据此自动算 未开始 / 进行中 / 已截止 |
| 4 | **只有作业的创建者本人能修改该作业**（方案 B） | 团队管理员也**不能**改别人布置的作业。这是用户明确选的 |
| 5 | 作业页含四个 tab | 简介 / 题目列表 / 排行榜 / 提交 |
| 6 | 提交可见性 | 普通成员**只能看自己的**提交；团队所有者和管理员能看**全部**（含代码） |
| 7 | 排行榜按 **IOI 计分** | 每题按测试点比例给分，取时间窗内最高分 |
| 8 | 每题满分**统一 100** | 不做逐题配分，`HomeworkProblem` 不带 Score 字段 |
| 9 | 截止后**仍可提交，但不计入排行榜** | 练习友好；榜单只统计 `[start, end]` 窗内的提交 |
| 10 | 站点超管（role=1）**拥有所有团队的全部权限** | 便于处理违规内容 |
| 11 | 本轮范围：**团队 + 作业核心** | 文件功能单独一轮，本轮不做（表也先不建） |

## 3. ⚠️ 计分：现状核实结果（实现前必读）

已核实代码，**测试点级别的分数数据是齐的**，但有一个必须先解决的卡点。

**已具备：**
- `model.JudgeResult`（`internal/model/submission.go:45`）：每个测试点一行，含 `CaseID` / `Status`。
- `model.Submission.Score`（同文件 :23）：字段已存在，注释即"OI/IOI 单次提交得分（测试点均分）"。
- `Worker.contestSubmissionScore`（`internal/judgeworker/worker.go:678`）：已实现
  `round(通过点数 / 总点数 × 该题满分)`。
- `model.UserContestProblem.Score`：IOI 已在做"取历史最高分"（`updateScoreContestStats`，worker.go:701）。

**卡点：**
```go
// internal/judgeworker/worker.go:375
if s.ContestID != 0 {
    s.Score = w.contestSubmissionScore(s.ContestID, s.ProblemID, caseResults)
}
```
`Score` **只在比赛提交时才算**。作业提交不属于任何 contest，直接沿用的话分数恒为 0。

**解决方案（本次采用）：**
给 `submissions` 加 `homework_id`（与现有 `contest_id` 对称，0 表示非作业提交），
worker 改成 `if s.ContestID != 0 || s.HomeworkID != 0` 时算分。
作业每题满分固定 **100**，不从关联表取（作业不做逐题配分，见 §9 待确认项）。

**为什么不复用 contest_id**：作业不是比赛，塞进 contest 会污染 rating、封榜、赛制等一整套逻辑。

## 4. 数据模型

新增 6 张表。项目**不做 AutoMigrate**，表结构由 `database/schema.sql` + `database/migrations/*.sql` 维护，
两处都要同步（schema.sql 内按表名字母序插入，保持 dump 顺序）。

```go
// ===== 团队 =====

// Team 团队
type Team struct {
    ID          int64  `gorm:"primaryKey"`
    Name        string `gorm:"size:60;not null"`
    Description string `gorm:"type:text"`          // Markdown，显示在概览页
    Visibility  int    `gorm:"not null;default:0"` // 0 公开 / 1 非公开(需邀请码)
    InviteCode  string `gorm:"size:32;not null;default:''"`
    OwnerID     int64  `gorm:"index"`              // 所有者（创建者），内部主键
    CreatedAt   time.Time
    UpdatedAt   time.Time
}

// TeamMember 团队成员
type TeamMember struct {
    ID       int64  `gorm:"primaryKey"`
    TeamID   int64  `gorm:"uniqueIndex:idx_team_member,priority:1"`
    UserID   int64  `gorm:"uniqueIndex:idx_team_member,priority:2"`
    Role     int    `gorm:"not null;default:0"` // 0 成员 / 1 管理员 / 2 所有者
    Remark   string `gorm:"size:30;not null;default:''"` // 备注名（真实姓名，老师认人用）
    JoinedAt time.Time
}

// ===== 作业 =====

// Homework 团队作业
type Homework struct {
    ID          int64  `gorm:"primaryKey"`
    TeamID      int64  `gorm:"index:idx_homework_team_start,priority:1"`
    Title       string `gorm:"size:100;not null"`
    Description string `gorm:"type:text"` // Markdown
    StartTime   time.Time `gorm:"index:idx_homework_team_start,priority:2"`
    EndTime     time.Time
    // CreatedBy 决定谁能改：方案 B —— 只有本人能改，团队管理员也不行
    CreatedBy int64 `gorm:"index"`
    CreatedAt time.Time
    UpdatedAt time.Time
}

// HomeworkProblem 作业题目关联，Sort 决定顺序
type HomeworkProblem struct {
    ID         int64 `gorm:"primaryKey"`
    HomeworkID int64 `gorm:"index;uniqueIndex:idx_hw_problem,priority:1"`
    ProblemID  int64 `gorm:"uniqueIndex:idx_hw_problem,priority:2"`
    Sort       int   `gorm:"not null;default:0"`
}

// ===== 文件 =====

// TeamFile 团队文件（平铺，不分文件夹）
type TeamFile struct {
    ID         int64  `gorm:"primaryKey"`
    TeamID     int64  `gorm:"index"`
    Name       string `gorm:"size:255;not null"` // 原始文件名
    StoredPath string `gorm:"size:512;not null"` // 落盘相对路径，不外泄
    Size       int64  `gorm:"not null"`
    UploaderID int64  `gorm:"index"`
    CreatedAt  time.Time
}
```

## 5. 排行榜算法（IOI）

对某个作业：

1. 取该作业的题目列表 `P`（按 sort）。
2. 取所有 `homework_id = :hid` 且 `created_at ∈ [start, end]` 的提交。
   → **截止后的提交不计入排行榜**（但允许提交，见 §9）。
3. 对每个 (成员, 题目)：分数 = 该窗口内所有提交的 `MAX(score)`。
4. 成员总分 = 各题最高分之和；已通过题数 = 得满分（100）的题数。
5. 排序：总分降序 → 同分时**达到该总分的时间早者靠前**
   （即各题取到最高分的那次提交时间里的最大值，越早越靠前）。

**实现方式：不建聚合表，用一条 GROUP BY 查询实时算。**
理由：团队规模是几十到几百人 × 几到几十题，实时聚合完全够；
而维护聚合表要动判题 worker 的写回路径（`updateScoreContestStats` 那一套），
风险和复杂度都高得多，还会有脏数据风险。

```sql
SELECT user_id, problem_id, MAX(score) AS best, MIN(created_at) AS first_best_at
FROM submissions
WHERE homework_id = ? AND created_at >= ? AND created_at <= ?
GROUP BY user_id, problem_id;
```
（`first_best_at` 需要子查询才精确，实现时注意：要的是"取到最高分的最早时间"，
不是"最早提交时间"。可先按 user 聚合出 best，再回表取达成时刻。）

## 6. 后端接口

### 团队
| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/team` | 公开（列表；带 `mine=1` 过滤我加入的） |
| GET | `/api/team/:id` | 公开团队任何人；非公开团队非成员只返回名称/简介/成员数 |
| POST | `/api/team` | 登录用户 |
| PUT | `/api/team/:id` | 所有者 + 管理员 |
| DELETE | `/api/team/:id` | 仅所有者 |
| POST | `/api/team/:id/join` | 登录用户（非公开需带 `inviteCode`） |
| POST | `/api/team/:id/quit` | 成员本人 |

### 成员
| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/team/:id/member` | 团队成员 |
| PUT | `/api/team/:id/member/:uid/role` | 仅所有者（设/撤管理员） |
| DELETE | `/api/team/:id/member/:uid` | 所有者 + 管理员 |

### 作业
| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/team/:id/homework` | 团队成员 |
| GET | `/api/homework/:hid` | 团队成员（未开始时成员看不到题目列表） |
| POST | `/api/team/:id/homework` | 所有者 + 管理员 |
| PUT | `/api/homework/:hid` | **仅该作业的 CreatedBy 本人**（方案 B） |
| DELETE | `/api/homework/:hid` | **仅 CreatedBy 本人**，或团队所有者兜底（防人走了删不掉） |
| GET | `/api/homework/:hid/rank` | 团队成员 |
| GET | `/api/homework/:hid/submission` | 成员只返回自己的；所有者/管理员返回全部 |
| POST | `/api/homework/:hid/submit` | 团队成员（带 problem displayId + code + language） |

### 文件
| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/team/:id/file` | 团队成员 |
| POST | `/api/team/:id/file` | 所有者 + 管理员 |
| GET | `/api/team/file/:fid/download` | 团队成员 |
| DELETE | `/api/team/file/:fid` | 所有者 + 管理员 |

**错误码**（`internal/common/errcode/`，沿用就近分段，实现时确认未被占用）：
团队不存在 / 非团队成员 / 邀请码错误（可复用 `40009`）/ 作业不存在 /
作业未开始 / 非作业创建者。

## 11. 验证要点

- 判题：作业提交的 `submissions.score` 确实按测试点比例落库（不是 0，也不是恒 100）。
- 权限：管理员改**别人**布置的作业应被拒（方案 B 的核心）。
- 可见性：普通成员调 `/api/homework/:hid/submission` 只拿到自己的；换管理员账号能拿到全部。
- 非公开团队：非成员看不到作业/成员/文件；邀请码错误被拒、正确后入队且长期有效。
- 排行榜：分数 = 时间窗内最高分；截止后的提交不影响榜单；同分按达成时间排序。
- 表结构：`schema.sql` 在全新库中能完整加载（`mysql -D 临时库 < database/schema.sql`）。
